# 0011. Serve the container with a Node server, not a static file server

**Status:** Accepted

## Context

The client is a Vite build — a folder of static files. The obvious container is
nginx serving `dist/`, and it would have been smaller and simpler.

But the story endpoint is a **server-side** concern by construction: the
Anthropic key must never reach the browser
([0006](0006-keep-the-api-key-server-side.md)), so narration is generated by
middleware that runs in the Vite server process. A static-only image would boot,
serve the game, and play perfectly — with narration silently absent. That failure
looks identical to a missing API key, which is the worst kind of failure to ship:
plausible, quiet, and misattributed.

`vite preview` already mounts the story handler and would have worked, but it
documents itself as a development convenience rather than a production server,
and it would have dragged Vite and its dependency tree into the runtime image.

## Decision

Ship `server.mjs`: ~120 lines of `node:http` that serve `dist/` and mount the
**same** story handler the dev server uses.

To make that possible without duplicating request handling,
`tools/story-plugin.mjs` now exports `createStoryHandler()`, and the Vite plugin
is a thin wrapper around it. One implementation, two mount points.

## Consequences

- The image is a small Node runtime rather than nginx: **261MB** on
  `node:22-alpine`, no Vite, running as an unprivileged user, `read_only` under
  compose.
- `npm start` runs the same server locally, so the production path is exercised
  outside Docker too.
- Static-file concerns are now ours: MIME types, SPA fallback, path-traversal
  rejection, and cache headers all live in `server.mjs` and are tested. A
  traversal attempt returns 403 and a missing asset returns 404 rather than
  falling back to `index.html`.
- **`dependencies` vs `devDependencies` became load-bearing**, because the
  runtime stage installs with `--omit=dev`. This immediately caught a
  pre-existing mislabelling: `@anthropic-ai/sdk` and `zod` were dev dependencies
  and the first container crashed on boot. See
  [DEPLOYMENT.md](../DEPLOYMENT.md#dependency-hygiene).
- The build stage runs the generator validation, so an image cannot be produced
  from a source tree that generates uncompletable caves.
