# Assets and the Blender pipeline

The character and props are generated by script in `blender/` and exported to
glTF. Nothing is modelled by hand, and the scripts are the source of truth.

```bash
npm run assets       # headless: blender/*.py -> public/models/*.glb
```

The same scripts also run inside a live Blender session over MCP, which is handy
for eyeballing a model while iterating — but the headless path is the
reproducible one: no GUI, no open file, no leftover scene state.

Files: `lib_build.py` (shared bmesh helpers), `build_character.py`,
`build_props.py`, `build_cavern.py` (**no longer built** — see below).

Two inspection helpers, not part of the build: `preview.py` renders a
three-quarter view of a named collection, and `preview_pose.py` renders the rig
at a given frame of a given action — the fastest way to check that a bone
rotation moves the way the animation intends without opening Blender.

## `model.blend` is an output, not an input

`blender/model.blend` (468KB, Blender 5.2.1) is a **saved session** — what you
get if you run the build scripts and hit save. It is committed so you can open
the rig and look at it, which is much faster than reading `build_character.py`
to find out how the eyebrows are parented.

> **It is not a source of truth, and the build never reads it.**
> `npm run assets` invokes Blender with `--factory-startup`, which starts from an
> empty scene and rebuilds everything from the Python. **Edits you make in
> `model.blend` are silently discarded by the next build.** To change an asset,
> change the script.

What is inside it:

| Collection | Contents |
|---|---|
| `TorchBoy` | `TorchBoyMesh` (1792 verts, 9 materials, armature-modified) and `TorchBoyRig` (14 bones) |
| `Props` | `Prop_Exit`, `Prop_Fuel`, `Prop_StairsUp`, `Prop_StairsDown`, `Prop_Treasure` |
| `Cavern` | 23 objects of level geometry — **from the retired pipeline**, see below |
| `Collection` | preview lights and cameras from `preview.py`, plus a leftover default `Cube` |

Three actions are on the rig: `Idle` (121 frames), `Walk` (25), `Gather` (30).

**The `Cavern` collection is stale by design.** It was built by
`build_cavern.py` from the old fixed levels — the object names still carry baked
secret coordinates (`L0_secret_10_5`). The game does not ship any of it: caves
are generated in the browser now
([adr/0001](../adr/0001-generate-caves-in-the-browser.md)). Treat those objects
as a museum piece showing what the retired pipeline produced, not as anything
the game loads.

Only `public/models/torchboy.glb` and `props.glb` are shipped, and both come
from the scripts.

## The bmesh rule that matters most

**Never hold bmesh element references, or indices, across a build.**

bmesh reallocates its element arrays as the mesh grows, invalidating every Python
`BMVert` handed out earlier — and indices are no better, because bevel's
deletions free slots that later geometry reuses and `index_update()` then
renumbers them.

Storing bone and material assignment in side tables left **1750 of 1792 vertices
with no vertex group**, so the whole mesh bound to glTF's `neutral_bone` and the
character never deformed. The clips played, the bones moved, and nothing on
screen budged — which is exactly the kind of bug that survives being looked at.

Assignment now lives **on the elements**: a deform layer for weights,
`BMFace.material_index` for materials.
[adr/0007](../adr/0007-bake-skin-weights-onto-bmesh-elements.md)

## Rigging and animation

**A bone's local Y runs along the bone.** Every bone here points +Z (world up),
so pose-space `location = (0, y, 0)` moves it vertically and `(0, 0, z)` moves it
forward/back. The walk and idle "bobs" were authored on local Z and pushed the
character back and forth instead of up.

**Clips are baked by sampling continuous functions**, not by hand-placing a few
keyframes: no Bezier handle overshoot, no flat spots at the extremes, and the
loop is seamless by construction because every term is periodic over the cycle.
`Idle` / `Walk` / `Gather` are all built this way.

**Blender 5.x moved F-Curves into slotted-action channelbags.** `action.fcurves`
is gone; the path is now `action.layers[].strips[].channelbags[].fcurves`.
`lib_build.fcurves_of()` supports both shapes.

## What is deliberately *not* built here

`build_cavern.py` is **not run** by `npm run assets`. Caves are generated in the
browser now, and the 2.4MB `cavern.glb` is gone.
[adr/0001](../adr/0001-generate-caves-in-the-browser.md)

The file is kept because it remains the **reference implementation for floor
height**: `src/game/Grid.js` is a line-by-line port of the same function and the
two must produce bit-identical values, or the player floats above or sinks into
the ground. `FLOOR_SUB` appears in both files and must stay in sync.

`tools/gen_levels.mjs` is likewise legacy and not run — superseded by
`src/game/LevelGen.js`.
