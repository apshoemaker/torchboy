# 0001. Generate caves in the browser, not as a baked mesh

**Status:** Accepted

## Context

Caves were originally generated by `tools/gen_levels.mjs` into
`public/data/levels.json`, which `blender/build_cavern.py` turned into a 2.4MB
`cavern.glb` that the game downloaded. The layout was fixed at build time, so
every run was the same three caves.

The game is about discovery. A cave you have already explored has nothing left to
find, which undercuts the entire premise on the second play.

## Decision

Generate the caves **in the browser at load**, per run
(`src/game/LevelGen.js` → `src/game/CavernMesh.js`), and validate each level
against its design invariants, re-rolling any that fail.

`build_cavern.py` and `gen_levels.mjs` are kept but no longer run.

## Consequences

- Every session is a different cavern.
- `public/` dropped to ~500KB; the 2.4MB mesh download is gone. Building ~68k
  triangles costs a few milliseconds.
- A generator can produce a *bad* level, so validation becomes load-bearing
  rather than a nicety. See [0010](0010-validate-the-generator-independently.md).
- `CavernMesh.js` is now a port of `build_cavern.py`, and the floor-height
  function must stay bit-identical between them or the player floats above or
  sinks into the ground. This is an ongoing cost and is listed as an architecture
  invariant.
- Levels can no longer be hand-tuned, so the generator has to encode what
  "good" means — hence the size band, the reward gating, and the reachability
  rules.
