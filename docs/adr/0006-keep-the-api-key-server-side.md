# 0006. The API key never reaches the browser

**Status:** Accepted

## Context

The story is generated by calling the Anthropic API. The game is a static
front-end built by Vite. Anything under `src/` is compiled into the bundle and
served to the client, where it is readable in devtools — so a key used from
client code is a published key.

## Decision

All model calls go through `tools/story-plugin.mjs`, Vite middleware that runs in
the server process and is mounted on both the dev server and `vite preview`. It
exposes exactly one endpoint, `POST /api/story/next`, and returns finished prose.

`.env` and `.env.*` are gitignored.

## Consequences

- The client never sees a key, a model name, or a prompt — only text.
- The story only works where that middleware runs. A purely static deploy gets
  the written fallback beats, which is acceptable because narration is a
  flourish.
- Vite does not put `.env` into `process.env` for plugins (it exposes only
  `VITE_`-prefixed variables, and only to client code), so `vite.config.mjs` has
  to load it explicitly for the server side.
- Any future server-side capability goes in the same place, and the same rule
  applies: `src/` is public.
- Verification is mechanical: `grep -rE "sk-ant|wrkspc_" dist/` must find nothing
  but documentation placeholders.
